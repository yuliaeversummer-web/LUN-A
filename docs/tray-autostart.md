# Дополнение к этапу 3: трей и автозапуск

## Поведение

- X главного окна вызывает штатный Tauri close. Rust перехватывает CloseRequested, скрывает окно и сохраняет настройки; процесс, трей, оверлей и регистрация Ctrl+D сохраняются. Кнопка «Свернуть» по-прежнему вызывает minimize и оставляет окно в панели задач.
- Двойной левый клик по иконке трея показывает main, снимает minimized и возвращает фокус. Правый клик открывает существующее меню. Меню на одиночный левый клик отключено, чтобы не мешать двойному.
- «Выход» устанавливает флаг quitting до сохранения настроек, снимает глобальные сочетания и вызывает app.exit(0). CloseRequested при quitting больше не перехватывается.
- Официальный tauri-plugin-autostart 2.7.0 регистрирует единственную запись LUNÉA с аргументом `--autostart`. При первом запуске регистрация не включается автоматически. Новых npm-зависимостей нет.
- «Запускать вместе с Windows» показывает результат plugin.is_enabled(), включая статус StartupApproved Windows. JSON не хранит дублирующий флаг включённой регистрации. Состояние перечитывается при открытии настроек, возврате фокуса main и после enable/disable; ошибки показываются, неизвестное состояние не выдается за выключенное.
- «Запускать свёрнутым в трей» хранится в прежнем desktop.json как startInTray, по умолчанию false. Старые файлы настроек совместимы через serde default.
- Главное окно создаётся скрытым. Только `--autostart` вместе с startInTray=true оставляет его скрытым, без промежуточного show. Обычный запуск показывает main независимо от startInTray. Автоматический повторный запуск не поднимает скрытое окно уже работающего экземпляра; ручной повторный запуск восстанавливает его через single-instance.
- configure_startup разрешена только main. Сырые permissions плагина autostart и создание окон из JS не добавлены. Четыре темы и MascotDisplay сохранены.

## Проверено

Проверки выполнены в debug Tauri на текущей Windows/WebView2. Артефакты: output/playwright/tray-autostart и output/tray-autostart-*.log (исключены из Git).

- npm run typecheck и npm run build: успешно.
- npm run tauri build: успешно, NSIS x64 19.70 MiB. Установщик: src-tauri/target/release/bundle/nsis/LUNÉA_0.1.0_x64-setup.exe. Code Integrity 4551 не повторилась; установка и повторный вход Windows не выполнялись.
- cargo test --lib: 3/3. Новый тест проверяет четыре комбинации automatic/startInTray, точный аргумент и миграцию старого JSON.
- X через настоящий WebView2: main visible=false, процесс и оба HWND сохранены, один tray_icon_app.
- «Свернуть»: main visible=true, IsIconic=true. Восстановление через существующий Rust open_main снимает minimized и показывает окно.
- Включение и выключение автозапуска через реальные checkbox: plugin status и HKCU Run совпали; после выключения запись отсутствует. Повторное enabled=true не создало новую регистрацию.
- Холодный запуск debug exe с `--autostart` и startInTray=true: оба окна скрыты, трей существует, Ctrl+D зарегистрирован; оверлей открывается отдельно, main остаётся скрытым.
- Холодный ручной запуск с startInTray=true: main видим. Холодный запуск с `--autostart` и startInTray=false: main видим.
- Повторные автоматический и ручной запуски: один процесс, два штатных окна, одна иконка; ручной запуск восстановил main.
- Значение startInTray восстановилось после перезапуска. Автозапуск после теста выключен, startInTray возвращён в false.
- Четыре темы нового раздела: без горизонтального overflow, оба переключателя доступны, page errors отсутствуют. ACL действительно отклоняет configure_startup из overlay.

## Непокрытые нативные сценарии

Помощник Computer Use остановился с сообщением об отсутствии поддержки URL policy для текущего Windows-браузера при выборе другого приложения для проверки глобальной клавиши. После этого нативный ввод через помощник не продолжался. Playwright и программные проверки собственной debug-сборки доступны отдельно.

Поэтому двойной клик по реальной иконке трея, клик «Выход» и новый end-to-end прогон Ctrl+D из другого приложения при скрытом main остаются ручной проверкой. Обработчики реализованы; штатный open_main и сохранённая регистрация сочетания проверены, но это не заменяет клики по трею. Завершения debug-процессов между холодными запусками использовались только для подготовки тестов и не считаются проверкой «Выход».

Фактический выход из учётной записи Windows не выполнялся. Проверен тот же аргумент запуска и сохранённый профиль; после реального повторного входа следует подтвердить отсутствие вспышки main, наличие одной иконки, Ctrl+D и восстановление двойным кликом. Также вручную проверить завершение через «Выход», отсутствие процесса и успешный последующий ручной запуск.

Автозапуск следует включать в установленной копии приложения: официальный плагин регистрирует путь текущего exe. Debug-регистрация во время QA снята. Системная защита и политики Windows не менялись. Реальные аудио/Discord-интеграции не добавлены.
