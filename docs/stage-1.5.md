# LUNÉA — этап 1.5

## Реализация

- Панель 44px с локальным векторным знаком, названием, подписью и иконками Lucide. Кнопка разворачивания меняет подпись и иконку после изменения состояния окна.
- `minimize()`, `toggleMaximize()`, `close()`, `startDragging()` и `startResizeDragging()` вызываются через Tauri Window API. Двойной основной щелчок распознаётся по второму mousedown, как в документации Tauri. Кнопки находятся вне области перетаскивания.
- После размонтирования снимается подписка на resize, включая случай незавершённой регистрации обработчика. Ошибки IPC показываются в панели и не превращаются в необработанные Promise rejection.
- Основное окно: `decorations:false`, `resizable:true`. Области захвата 5px по сторонам, 8px по углам передают изменение размера Windows; собственного расчёта размера, Win32 hooks и новых Rust-команд нет. При разворачивании области исчезают. `shadow:false` исключает скрытые отступы декорированной тени Windows при проверке минимального размера; основной размер 1100×720, минимальный 850×560 сохранены.
- Одна прокручиваемая область `.content-scroll` с `min-height:0`, `overflow-y:auto`, видимым фокусом и `tabindex=0`. Title bar, sidebar, хлебные крошки и footer остаются на месте. Ползунок находится внутри отдельного правого отступа, вне полосы ресайза.
- Нативный скроллбар 6px по обеим осям, радиус 999px, цвет акцента с прозрачностью 48%, hover 85%. Есть fallback через scrollbar-color/scrollbar-width для движков без WebKit-псевдоэлементов. Переменные общие для четырёх существующих тем.
- В браузере кнопки управления ОС отключены и подписаны «Доступно в приложении Windows». В Tauri это реальные операции, а не имитация.
- Оверлей: `decorations:false`, `create:false`; маршрут не получил Title Bar или resize-области основного окна.

## Разрешения

Capability действует только для `windows:["main"]`, без remote origins:

| Permission | Назначение |
|---|---|
| `core:window:allow-minimize` | Свернуть |
| `core:window:allow-toggle-maximize` | Развернуть / восстановить |
| `core:window:allow-close` | Закрыть |
| `core:window:allow-start-dragging` | Переместить |
| `core:window:allow-start-resize-dragging` | Штатный ресайз за край |
| `core:window:allow-is-maximized` | Иконка и состояние областей ресайза |
| `core:event:allow-listen` | Слушать изменение размера |
| `core:event:allow-unlisten` | Снять обработчик |

Не включены `core:default`, `core:window:default`, filesystem, shell, создание окон, внешние origins. Для overlay этот capability не назначен.

## Проверки

Область проверки: обычное и развёрнутое окно; обе стороны переключателя maximize; минимизация и возврат; закрытие и повторный запуск; перемещение и ресайз; четыре темы; длинные страницы настроек и обзора; клавиатура, колесо и ползунок; исключение панели из overlay. Дополнительные сценарии: браузер без Tauri API и переход на overlay с последующим возвращением (снятие/повторная установка слушателя).

- `npm run typecheck` и `npm run build` — успешно.
- Debug-сборка Rust с capability — успешно; настоящее окно WebView2 открыто.
- Нативные кнопки свернуть, развернуть/восстановить и закрыть проверены. После операций обновляется видимая иконка; приложение перезапускается.
- Двойной щелчок выполнен через Playwright, подключённый к реальному WebView2 по локальному CDP, без моков IPC. После исправления блокировки drag-команды показана кнопка «Восстановить окно».
- Нативное перемещение подтверждено изменением screenX/screenY; нативное уменьшение окна подтверждено отдельным снимком.
- Edge / Playwright, 1100×720 и 850×560: Title Bar 44px; scrollbar 6px; документ не прокручивается; единственный вертикальный scroll-контейнер — `content-scroll`.
- Четыре темы: меняются фон панели и цвет ползунка; Crimson Night восстановилась после перезагрузки. По окончании возвращена Neon Pink.
- Клавиатура End/Home, колесо, перетаскивание реального ползунка — успешно. На странице настроек 850×560 клавиша End достигла `scrollTop=375`, `clientHeight=415`, `scrollHeight=790`; низ страницы полностью доступен.
- Sidebar остаётся на y=44, Title Bar на y=0, footer заканчивается на y=560; горизонтальной прокрутки нет. Навигация и отдельный `/overlay` работают, в overlay нет `.titlebar`.
- Финальный проход браузерных сценариев: нет ошибок console/pageerror. Снимки и диагностические результаты сохранены в `output/playwright/stage-1.5/` (каталог исключён из Git).

После изменения `shadow:false` финальная конфигурация успешно прошла `cargo build`. Повторное визуальное подтверждение точного нативного минимума 850×560 не завершено: помощник Windows вернул `user input was detected in this window` при восстановлении свёрнутого тестового окна. Продолжать ввод в конфликте с пользовательским не стал. Нативное уменьшение проверено до изменения тени; точные 850×560 и полная прокрутка подтверждены в браузере.

Физический тачпад отдельно не проверялся: сохранена нативная прокрутка без перехвата wheel/touch событий. Проверки браузерных сценариев и нативных операций различаются; это не заявление об автоматизации всех сценариев внутри WebView2. Проверки выполнены на текущем Windows 11 / WebView2, отдельная машина Windows 10 не использовалась.

## Release: ошибка 4551

Повтор `npm run tauri build` снова завершился блокировкой Windows. В этот раз запрещён запуск `src-tauri/target/release/build/vswhom-sys-b9232724f5d33719/build-script-build.exe` (crate `vswhom-sys 0.1.3`); в этапе 1 блокировался build-скрипт `zmij 1.0.23`. Это показывает, что проблема не ограничена одной зависимостью. Журнал `Microsoft-Windows-CodeIntegrity/Operational`, событие 3077, подтверждает нарушение требований подписи / политики Code Integrity. Тип политики (корпоративная App Control или Smart App Control) нельзя надёжно определить только по тексту этой ошибки.

Защита и политика не изменялись. Установщик не создан. Безопасные варианты:

1. Администратор действующей политики может рассмотреть узкое разрешение проверенного подписанта или конкретных артефактов сборки. Правила по хешу меняются при пересборке; одного разрешения итогового lunea.exe недостаточно для Cargo build-скриптов. Это требует самостоятельного решения администратора, а не автоматической правки агентом.
2. Собирать в одобренной среде разработки / Windows CI или VM, где политика допускает доверенную сборочную цепочку, сохраняя защиту текущего компьютера. Для распространения — настроить доверенную подпись полученного приложения и установщика.
3. Сначала определить блокирующую policy по событиям Code Integrity; повторная установка Node/Rust, запуск от администратора и исключение каталога из антивируса сами по себе не решают требования App Control.

Источники: [диагностика App Control](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/operations/appcontrol-debugging-and-troubleshooting), [правила App Control](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/design/select-types-of-rules-to-create), [Smart App Control и подписи](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/overview), [кастомный заголовок Tauri](https://v2.tauri.app/learn/window-customization/).

## Запуск

`npm run tauri dev` — нативное приложение. Перед запуском закройте отдельный `npm run dev`, если он уже занял порт 1420. `npm run dev` — браузерный просмотр с отключёнными кнопками управления ОС. `npm run tauri build` — release/установщик, пока блокируется политикой Windows.
